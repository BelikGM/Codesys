# "60 Лет Октября" — полный контекст объекта

Этот файл — саммари всего, что известно об объекте, для быстрого
восстановления контекста в новой сессии чата. Технические детали
логики — в `LOGIC.md`, экраны — в `SCREENS.md`.

## Общее

- Контроллер: ОВЕН СПК107, CODESYS 3.5, язык ST
- Проект сделан на основе **ДДЮТ** (фонтан детского центра), который
  в свою очередь на основе **Саки Пруд**
- Дозация (pH/альгицид/биопаг) на "60 Лет Октября" **не наша** —
  вынесена на отдельный контроллер, экраны скрыты из меню
- Добор воды **не наш** — решает внешнее оборудование "Мусидора" по
  своим уровням; мы зеркалим её команду на выход и проверяем реле
  подтверждения (обрыв/залипание)

## Шины Modbus

- COM1 (9600, 8N1): МВ110-16Д (дискретные входы DI1-DI12), МУ110-16Р
  (дискретные выходы, используются только DO1-DO4)
- COM2 (38400): EMD-PUMP насосы-шоу (не фильтрационные)
  - Адрес 41 — EMD_PUMP_1
  - Адрес 42 — EMD_PUMP_2
  - Адрес 43 — EMD_PUMP_3 (**нужно добавить в дереве Modbus вручную**,
    без этого `PRG_Pumps.st` не скомпилируется — используется
    `EMD_PUMP_3.xError` в блоке 4а)

## Тайминги аварий реле (подтверждено пользователем)

- Сухой ход (DO1/DI8): **2 секунды**
- Насосы фонтана (DO2/DI9): **2 секунды**
- Подсветка (DO3/DI10): **2 секунды**
- Фильтрация, ручной режим (DI12/DI7): **2 секунды**
- Клапан добора (DO4/DI6): **20 секунд** (единственное исключение —
  механический процесс открытия/закрытия не мгновенный)

## Поведение аварий реле (изменено 21.07.2026)

**Все пять** аварий реле — сухого хода (DO1/DI8), клапана добора
(DO4/DI6), насосов фонтана (DO2/DI9), подсветки (DO3/DI10) и
фильтрации в ручном режиме (DI12/DI7) — сделаны **живыми
(самосброс)**: флаг присваивается напрямую из `.Q` таймера, поэтому
как только команда и обратная связь снова совпали, авария уходит
сама. Раньше все пять были защёлками и снимались только `xAlarmReset`.

Кнопка «Сброс аварий» (`xAlarmReset`) **оставлена на экране по
решению пользователя**, хотя после этой правки не снимает ни одной
аварии — служит только квитированием и пишет в журнал строку
«Сброс всех аварий». Если понадобится — можно убрать с экрана.

## Логика опасной ситуации (подтверждено)

- Ничего не блокируется — чисто напоминание оператору
- Показ по фронту появления условия (сухой ход + ручная фильтрация)
- Кнопка "ОК" пишет `xConfirmDangerDialog := TRUE`, остальное делает
  код (гасит видимость, сбрасывает флаг)
- Если условие уйдёт и появится снова — диалог покажется повторно

## Открытые вопросы / решения, принятые без явного подтверждения

1. **Кнопка ручного пуска НФ с экрана** — пользователь подтвердил,
   что кнопка должна работать при DI11=1 (Авто режим переключателя),
   но в финальной версии кода **убрана целиком**, т.к. физического
   выхода под управление насосом фильтрации нет (все 4 DO заняты).
   Если найдётся свободный выход — нужно вернуть с полноценной
   логикой пуска/остановки.
2. **Адрес EMD_PUMP_3** — предположен 43 по аналогии с 41/42,
   пользователь должен подтвердить/поправить в реальном проекте.
3. Сравнение для аварии насосов/света идёт с **уже вычисленной
   командой этого цикла** (`xPumpsCmd`, `xLightCmd`), а не с
   `xDO[2]`/`xDO[3]` — это осознанный выбор (без задержки на скан),
   не обсуждался явно, но логически корректен и симметричен с
   исправлением бага сухого хода.

## Структурные изменения 23.07.2026

1. **Порядок вызова в PLC_PRG исправлен.** Сборка маски выходов МУ110
   вынесена из `PRG_IO` в новый POU `PRG_IO_Write`, вызывается ПОСЛЕ
   `PRG_Fountain` — устранена задержка выходов на 1 скан. `PRG_IO`
   теперь только читает входы + безопасная инициализация МУ110.
2. **Аварии реле — самосброс** (сделано ранее): все пять живые,
   `xAlarmReset` фактически ничего не снимает (кнопка оставлена).
3. **Коррекция ухода RTC** — новый POU `PRG_TimeCorrect`: раз в сутки
   в `iTimeDriftCorrHour` (03:00) отводит часы на `iTimeDriftCorrSec`
   (15с) назад. ⚠️ сигнатуру `SysTimeRtcSet` проверить в проекте.
   ⚠️ **ГРАБЛИ 03.08.2026 (вскрыты на ДДЮТ, лечение перенесено сюда):**
   часы уезжали назад ровно на 3 ч (10800 с = `iTimeZoneOffsetSec`) за
   каждую загрузку с холодным сбросом: 14:25 → 11:25 → 8:25 → 5:25.
   Причина 1 — на СПК `SysTimeRtcGet` отдаёт UTC, а `SysTimeRtcSet`
   трактует аргумент как МЕСТНОЕ время (рантайм сам вычитает пояс);
   код читал UTC и писал его обратно. Причина 2 — `iLastCorrDay`
   RETAIN, холодный сброс ставил его в -1, и условие
   `(iCurrentDay <> -1) AND (час >= 3)` было истинно на ПЕРВОМ скане,
   т.е. коррекция шла на каждой загрузке, а не раз в сутки.
   Лечение в `PRG_TimeCorrect`: холодный старт только запоминает день;
   после записи RTC читается обратно на следующем скане, отклонение
   >60 с копится в `diRtcSetBias` и вычитается из всех записей
   (перекос ПЛК меряет сам) с немедленной повторной записью; 2 неудачи
   подряд → `xTimeDriftCorrEnable:=FALSE` + текст на экран; шаг
   коррекции ограничен 600 с. `diRtcSetBias` должен показать -10800.
4. **Журнал аварий на SD** — новый POU `PRG_AlarmLogSD`: по фронту
   каждой из 11 аварий дописывает "чч:мм дд.мм.гггг - название" в файл
   на SD. Путь SD на СПК: `/mnt/ufs/media/mmcblk0p1/` (док ОВЕН
   «Архивация — СПК»), библиотека **CAA File** (добавить в дерево!),
   карта FAT32/MBR. Тип дескриптора — `FILE.CAA.HANDLE` (НЕ
   `CAA.HANDLE` — иначе ошибка «ссылка на объект не указывает на
   экземпляр»). Строки пишутся как **WSTRING/UTF-16LE** + BOM
   (кириллица читается на ПК). Сделано в ОБОИХ проектах (в ДДЮТ свой
   набор из 12 аварий). RETAIN-журналы (ПЧ/уставки) пока НЕ
   переносились — это отдельный, более крупный шаг.

## РОТАЦИЯ ЖУРНАЛОВ НА SD (04.08.2026)

Раньше три файла на карте росли бесконечно: ни лимита, ни очистки.
Теперь **файлы помесячные** и есть **сторож свободного места**.

- Имена: `alarms-MM-YYYY.log`, `pump_changes-MM-YYYY.log`,
  `setpoints-MM-YYYY.log`. Новый месяц → новый путь → старый автомат
  сам создаёт файл (OPEN → NOT_EXIST → CREATE + BOM). Отдельной
  логики «переключение месяца» НЕТ намеренно: пропущенная граница
  (ПЛК был выключен) отрабатывается сама при первой же записи.
- `FB_SdSpaceGuard` раз в час (`tSdCheckPeriod`), при смене месяца и
  после неудачной записи обходит каталог и чистит самый старый месяц
  по ДВУМ независимым условиям — и повторяет, пока условие держится.
- **Единственная настройка — номинал карты в выпадающем списке на
  экране** (`iSdCardSize`, 0=2 ГБ … 6=128 ГБ). Реальные ёмкости — в
  таблице `audiSdCardMB` (1800 / 3600 / 7200 / 14500 / 29000 / 58000 /
  116000 МиБ). Числа взяты с запасом ВНИЗ: производитель считает ГБ
  десятичными (32 ГБ = 32·10⁹ Б = 30518 МиБ), плюс место съедают
  таблица разделов, две копии FAT и корневой каталог. Занижать
  безопасно, завышать нельзя.
- **Условие A — КВОТА (работает всегда).** Квота считается сама:
  `квота = ёмкость − 100 МБ резерва − чужие файлы в каталоге`.
  На 32 ГБ журналам достаётся ~28,9 ГБ, на 2 ГБ ~1,7 ГБ. Наши журналы
  переросли квоту → чистим. В квоту считаются ТОЛЬКО файлы, прошедшие
  разбор `F_SdLogMonthKey`; чужие вычитаются из ёмкости, но удалению
  не подлежат. ⚠️ Содержимое вложенных папок не считается — DirList
  в глубину не ходит; папку `app.spk1xxm01` с проектом (единицы МБ)
  перекрывает резерв.
- **Аварийный форс.** Если запись не проходит `cWriteFailForce` (3)
  раз подряд — карта реально полна, что бы ни говорил расчёт по
  номиналу (в списке выбрали 32 ГБ, а стоит 16). Тогда самый старый
  месяц удаляется безусловно. Одиночный сбой к удалению не приводит.
- **Самый старый** ищется по числовому ключу `YYYY*12 + MM - 1`, а не
  по строке: иначе `12-2025` оказалось бы «новее» `01-2026`.
- Файл текущего месяца удалить нельзя в принципе (кандидат обязан
  быть строго старше).
- Удаляются ТОЛЬКО имена, прошедшие полный разбор в
  `F_SdLogMonthKey` (длина, префикс, цифры, разделители, диапазоны
  MM 1..12 и YYYY 2000..2199). Любой чужой файл на карте не тронут.
- ⚠️ Свободное место напрямую спросить НЕЛЬЗЯ: в CAA File нет ни одного
  ФБ свободного места (проверен полный список ФБ), в SysFile тоже
  (проверен полный список функций). Поэтому ёмкость берём иначе —
  `FB_SdCardSize` читает размер раздела у ядра из
  /sys/block/mmcblk0/mmcblk0p1/size ОБЫЧНЫМ чтением файла через CAA
  File: без доп. библиотек, без правки CODESYSControl.cfg и без
  блокировки задачи. Число там — секторы по 512 Б.
- Если удалять уже нечего, а квота всё равно превышена (вся история —
  один текущий месяц, раздутый дребезгом аварий), поднимается
  `xSdLogQuotaStop` и запись на карту ПРЕКРАЩАЕТСЯ. Карта не
  переполнится никогда, фонтан работает, экранные журналы ведутся.
  Снимается САМО на следующем месяце — человек не нужен.
- Алгоритмы (разбор имён, выбор старого месяца, разбор ёмкости,
  единицы) прогнаны на исполняемой модели — `docs/sd_guard_model_test.js`,
  165 проверок, `node sd_guard_model_test.js`.
5. **Дозация** на «60 лет» не нужна вообще (отдельный контроллер) —
   подтверждено 23.07.2026, вопрос доз снят.
