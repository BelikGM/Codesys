# "60 Лет Октября" — логика автоматики (по коду, версия после исправления 2 багов)

Проект на CODESYS 3.5 (ST), контроллер ОВЕН СПК107. Сделан на основе
проекта "ДДЮТ" (фонтан), который в свою очередь сделан на основе
"Саки Пруд". Дозация (pH/альгицид/биопаг) в этом проекте **не наша** —
управляется другим контроллером. Добор воды **не наш** — решает
внешнее оборудование "Мусидора" по своим уровням, мы только
зеркалим её команду на выход и проверяем реле.

## Карта входов/выходов

### DI (МВ110-16Д)
| DI | Назначение | Переменная |
|---|---|---|
| DI1 | ПЧ1 (насос-шоу), информационный | `xPump1Work` |
| DI2 | ПЧ2 (насос-шоу), информационный | `xPump2Work` |
| DI3 | ПЧ3 (насос-шоу), информационный | `xPump3Work` |
| DI4 | Сухой ход от Мусидоры, 1=норма | `xDryRunOk` |
| DI5 | Пуск добора от Мусидоры (автоматика) | `xDamperCmdRaw` |
| DI6 | Подтверждение положения клапана добора | `xDamperRelayFb` |
| DI7 | Контактор фильтрации (НФ физически работает) | `xNfWork` |
| DI8 | Подтверждение реле сухого хода | `xDryRunRelayFb` |
| DI9 | Подтверждение работы насосов фонтана | `xPumpRelayFb` |
| DI10 | Подтверждение работы подсветки | `xLightRelayFb` |
| DI11 | Ручка режима фильтрации = АВТО | `xNfAutoSwitch` |
| DI12 | Ручка режима фильтрации = РУЧНОЙ | `xNfManualSwitch` |

### DO (МУ110-16Р)
| DO | Назначение | Формула |
|---|---|---|
| DO1 | Дубляж сухого хода | `= xDryRunOk` (то есть `= DI4`) |
| DO2 | Пуск насосов фонтана | см. блок "Насосы фонтана" |
| DO3 | Пуск подсветки | см. блок "Подсветка" |
| DO4 | Дубляж клапана добора | `= xDamperCmdRaw` (то есть `= DI5`) |
| DO5–DO16 | Свободны | `FALSE` |

DI1–DI3 (ПЧ) читаются, но нигде в логике фонтана не участвуют — это
чисто информационные насосы-шоу, отслеживаются только на уровне
`PRG_Pumps.st` (связь по Modbus, авария связи).

## Сухой ход (PRG_Fountain, блок 3)

`xDryRunAlarm := NOT xDryRunOk` — живая переменная, пересчитывается
каждый цикл, НЕ защёлка. Это самая приоритетная авария в проекте —
первая в списке `sAlarmCauses` и первая проверяемая в `PRG_Errors.st`.

Блокирует автоматическое управление насосами (DO2) и подсветкой
(DO3), но НЕ блокирует ручной форс-пуск с экрана (`xPumpsForceOn`,
`xLightForceOn`) — оператор может вручную включить узел даже при
сухом ходе.

**Авария реле сухого хода** (`xDryRunRelayAlarm`, **живая**): таймер
2 секунды на несовпадение `xDryRunOk` (то, что уйдёт на DO1 в этом
же цикле) и `xDryRunRelayFb` (DI8). Обрыв — если подали 1, а DI8
не подтвердил; залипание — если подали 0, а DI8 всё ещё 1.
**Самосброс**: флаг = `tonDryRunRelayAlarm.Q` напрямую, как только
сигналы снова совпали — авария уходит сама, кнопка `xAlarmReset`
для неё не нужна.

## Клапан добора (PRG_Fountain, блок 4)

Решение "нужен добор или нет" принимает Мусидора — мы полностью
зеркалим её сигнал `DI5 → DO4`, никакой собственной логики принятия
решения нет.

`sDamperPosition` — статус позиции по **факту** (DI6), а не по
команде: "Открыт" если `xDamperRelayFb=TRUE`, иначе "Закрыт".

**Авария реле клапана** (`xDamperRelayAlarm`, **живая, самосброс**):
таймер **20 секунд** (дольше остальных — механический процесс
открытия/закрытия не мгновенный) на несовпадение `xDamperCmdRaw`
(DI5) и `xDamperRelayFb` (DI6). Клапан дошёл до положения — авария
снимается сама.

## Фильтрация (PRG_Fountain, блок 5)

Два входа переключателя режима: DI11 (Авто) и DI12 (Ручной).
`sNfModeStatus`: "Авто" если DI11, "Ручной" если DI12, "?" если ни
один вход не активен (обрыв линии или промежуточное положение).

**Авария реле фильтрации в ручном режиме** (`xNfManualRelayAlarm`,
**живая, самосброс**): в ручном режиме (DI12=1) насос фильтрации
должен работать постоянно; таймер 2 секунды на условие
`DI12=1 AND DI7=0`. Насос запустился или ручку увели из ручного
режима — авария снимается сама.

В автоматическом режиме (DI11=1) фильтрация работает по своему
внутреннему графику (обычно 3ч/3ч) — контроллер в этот процесс не
вмешивается и не проверяет.

**Кнопка ручного пуска фильтрации с экрана** — в этой версии
**отсутствует**, физического выхода под неё нет.

## Промывки НФ (PRG_Fountain, блоки 5а–5б)

Алгоритм не менялся относительно ДДЮТ: двухстадийный детект по
`xNfWork` (DI7) — промывка = 2 коротких включения подряд, каждое
дольше 1 минуты и короче `iFilterMinRunMin`. Между стадиями сбрасывается,
если случился полноценный подтверждённый запуск (`xNfHealthy`).

Сброс счётчика — свой отдельный диалог: `xAskResetNfFlush` →
`xConfirmResetNfFlush` (реальный ST-код в PRG_Fountain, пишет в
журнал изменений) → `xAskResetNfFlush:=FALSE`. НЕ сбрасывается через
`xAlarmReset` (принцип "сброс аварий ≠ сброс статистики").

## Насосы фонтана (PRG_Fountain, блок 9)

```
xPumpsCmd := xVseSist AND NOT xDryRunAlarm AND xManualPermissionNasos AND xSchedulePumpOut;
IF xPumpsForceOn THEN xPumpsCmd := TRUE; END_IF;   // ручной пуск, минуя всё
```

`iPumpSelect` (RETAIN, 0=Ручной/1=Выкл/2=Авто) раскладывается в блоке
2а на `xManualPermissionNasos` (TRUE при 2) и `xPumpsForceOn` (TRUE
при 0). При "Авто" решение принимает расписание (`FB_FountainSchedule`,
не меняно от ДДЮТ, режимы 0=Авто/1=Вкл/2=Выкл, БЕЗ "Астро").

**Авария реле насосов** (`xPumpRelayAlarm`, **живая, самосброс**):
таймер 2 секунды на несовпадение `xPumpsCmd` и `xPumpRelayFb` (DI9).

## Подсветка (PRG_Fountain, блок 10)

Та же схема, что насосы:
```
xLightCmd := NOT xDryRunAlarm AND xVseSist AND xLightEnable AND xScheduleLightOut;
IF xLightForceOn THEN xLightCmd := TRUE; END_IF;
```
`iLightSelect` (0=Ручной/1=Выкл/2=Авто), расписание с 4 режимами
(0=Авто/1=Вкл/2=Выкл/3=Астро, дефолт 3). Авария реле подсветки
(`xLightRelayAlarm`, **живая, самосброс**) — 2 секунды, DO3 vs DI10.

## Опасная ситуация: сухой ход + ручная фильтрация (PRG_Fountain, блок 12)

```
xDangerCondition := xDryRunAlarm AND xNfManualSwitch;
```
Живая переменная. Ничего не блокирует — только предупреждение.
Диалог показывается по фронту появления (`xShowDangerDialog:=TRUE`
при переходе 0→1). Кнопка "ОК" на диалоге выполняет:
```
GVL_Fountain.xConfirmDangerDialog := TRUE;
```
Остальное делает ST-код — гасит `xShowDangerDialog` и сбрасывает
`xConfirmDangerDialog`. Если ситуация уйдёт и появится заново —
диалог покажется снова. Эта авария **не входит** в общий счётчик
`iErrorsFountain` и в `sAlarmCauses` — у неё своя отдельная
индикация, чтобы не создавать нестыковку между текстом аварий и
их количеством.

## Общая авария (PRG_Fountain блок 11, PRG_Errors.st)

```
xAlarmFountain := xDryRunAlarm OR xDryRunRelayAlarm OR xDamperRelayAlarm
                OR xPumpRelayAlarm OR xLightRelayAlarm OR xNfManualRelayAlarm;
```

Порядок в `sAlarmCauses` и порядок проверки в `PRG_Errors.st` —
**сухой ход первым**, как самая опасная авария. Далее: реле сухого
хода → реле клапана → реле насосов → реле подсветки → реле
фильтрации (ручной режим) → связь ПЧ1/ПЧ2/ПЧ3 → связь МВ-Д/МУ.

## Что убрано из логики ДДЮТ (переменные оставлены в GVL_Fountain.st как "не используется", не удалены)

- Вся долговая система дозации pH/альгицид/биопаг
- Старая система 2/3 датчиков уровня и гистерезисов
- Старая система попыток добора (`iRefillAttempts`, `tRefillDurHours` и т.п.)
- Селектор заслонки `iDamperSelect` (заслонка теперь просто зеркало)
- Ручные форс-кнопки заслонки (`xDamperForceOpen/Close`)

## Известные баги, найденные и исправленные при ревизии

1. **PRG_Fountain, блок 3**: сравнение шло с `xDO[1]` (значение
   ПРОШЛОГО цикла, т.к. запись в xDO происходит позже в том же
   скане) — заменено на `xDryRunOk` (текущее значение этого цикла).
2. **PRG_Pumps.st, блок 4а**: было жёстко прописано только 2 насоса
   (`EMD_PUMP_1`/`EMD_PUMP_2`), при `cPumpCount=3` третий насос не
   проверялся бы на обрыв связи. Добавлен `EMD_PUMP_3`.
3. **PRG_Fountain, блок 5**: `CASE TRUE OF` — недопустимая
   конструкция в CODESYS (метка CASE требует целочисленный литерал).
   Заменено на `IF/ELSIF/ELSE`.
