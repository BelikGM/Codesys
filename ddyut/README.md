# ДДЮТ — автоматика фонтана (ОВЕН СПК107 / CODESYS 3.5)

Фонтан Дворца детского и юношеского творчества. Проект сделан на основе
более раннего **"Саки Пруд"**: архитектура шин/входов и долговая система
дозации перенесены почти без изменений, остальное серьёзно переработано
или добавлено с нуля.

В отличие от `60-let-oktyabrya` (который, в свою очередь, сделан на
основе этого проекта), здесь контроллер отвечает за **весь** цикл:
дозацию pH/альгицида/биопага, насосы фонтана, свет с расписанием (в т.ч.
по закату), заслонку добора воды, фильтрацию и промывки НФ, аварийную
сигнализацию, счётчики наработки и журналы изменений параметров.

## Структура

- `src/` — все файлы .st проекта (GVL, PRG, FB, F-функции), 21 файл
- `docs/CONTEXT.md` — контекст объекта, шины Modbus, карта DI/DO,
  порядок вызова
- `docs/LOGIC.md` — обязательные технические правила CODESYS
  (проверенные на практике грабли) + логика по разделам
- `docs/SCREENS.md` — все экраны визуализации, привязки переменных,
  диалоги, флаги видимости

## Шины Modbus

- COM1 (9600, 8N1): МВ110-16Д адр. 1 (дискретные входы),
  МУ110-16Р адр. 2 (дискретные выходы)
- COM2 (38400): EMD-PUMP адр. 41 (ПЧ1), адр. 42 (ПЧ2) — `cPumpCount := 2`

Аналогового модуля МВ110-8А на ДДЮТ нет.

## Порядок вызова

```
PRG_IO() → PRG_Fountain() → PRG_Pumps() → PRG_Errors()
```

## Файлы src/

Глобальные переменные:
- `GVL.st` — Modbus, ПЧ-насосы, журнал ПЧ (`aPumpLog`)
- `GVL_Fountain.st` — все переменные фонтана, журнал изменений
  (`aFountainLog`), уставки, счётчики

Программы:
- `PLC_PRG.st` — главная программа (MainTask)
- `PRG_IO.st` — распаковка DI, сборка маски DO
- `PRG_Fountain.st` — вся автоматика фонтана: уровень/сухой ход, добор,
  дозация, свет, НФ, промывки, журнал изменений (самый большой файл)
- `PRG_Pumps.st` — обработка ПЧ-насосов фонтана (COM2)
- `PRG_Errors.st` — подсчёт общих аварий

Функциональные блоки:
- `FB_SunsetRelay.st` — расчёт времени заката (рефракция 90.833°,
  будни/выходные по алгоритму Зеллера)
- `FB_FountainSchedule.st` — режимы расписания света и насосов,
  флаги видимости для экрана
- `FB_TimeZoneSelect.st` — выбор часового пояса (24 позиции)
- `FB_Pump.st` — обработка одного ПЧ

Функции:
- `F_FormatLogTimestamp.st`, `F_FormatLogDateOnly.st` — форматирование
  даты/времени для журналов
- `F_FountainLogWrite.st`, `F_PumpLogWrite.st` — запись в журналы
  со сдвигом (позиция 1 — всегда самая свежая)
- `F_SelectModeText.st` — текст 3-позиционного селектора (0/1/2)
- `F_LightScheduleModeText.st` — текст режима расписания света (0..3)
- `F_PumpScheduleModeText.st` — текст режима расписания насосов (0..2)
- `F_FaultCodeToText.st` — расшифровка кодов аварий ПЧ

## Файлы, сохранённые но НЕ вызываемые

Оба остались в проекте физически, вызовы закомментированы в `PLC_PRG.st`:

- `PRG_PR200.st` — ПР200 на объекте пока нет, но может появиться.
  Чтобы вернуть: раскомментировать `PRG_PR200()` и поднять канал slave
  в дереве Modbus.
- `PRG_PolivSPK.st` — резерв полива СПК; на ДДЮТ нет ямы слива,
  физически не нужен.

## Ключевые особенности логики

Подробно — в `docs/LOGIC.md`, здесь только самое важное:

- **Единый 3-позиционный селектор** (0=Ручной пуск / 1=Выкл / 2=Авто)
  применён к шести узлам с физическим DO: `iPumpSelect`, `iPhSelect`,
  `iAlgSelect`, `iBioSelect`, `iLightSelect`, `iDamperSelect`.
  RETAIN — на самом селекторе, не на производных флагах.
- **Сброс аварий ≠ сброс статистики**: `xAlarmReset` трогает только
  защёлки аварий, никогда не счётчики, попытки добора и промывки НФ.
- **Три разные кодировки режимов** — не путать между собой:
  селекторы `0=Ручной/1=Выкл/2=Авто`, расписание света
  `0=Авто/1=Вкл/2=Выкл/3=Астро`, расписание насосов `0=Авто/1=Вкл/2=Выкл`.
- **Журналы — массивы коротких строк**, не одна растущая строка
  (`WCONCAT` в CODESYS ограничен ~255 символами независимо от
  объявленного размера WSTRING — см. `docs/LOGIC.md`).
- Экран журнала привязывается **только к фиксированным индексам**
  (`aLog[1]`, `[2]`, …), никогда к вычисляемым.
