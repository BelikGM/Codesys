--- ГРАБЛИ 03.08.2026: ЧАСЫ УЕЗЖАЛИ НА -3 Ч ЗА КАЖДУЮ ЗАГРУЗКУ ---
Симптом: дата верная, время на 3/6/9 часов меньше реального
(14:25 → 11:25 → 8:25 → 5:25), шаг ровно 10800 с = iTimeZoneOffsetSec.
Причина 1: на СПК SysTimeRtcGet отдаёт UTC, а SysTimeRtcSet трактует
аргумент как МЕСТНОЕ время — рантайм при записи сам вычитает пояс.
PRG_TimeCorrect читал UTC и писал его обратно → каждая запись минус 3ч.
Причина 2: iLastCorrDay — RETAIN, холодный сброс ставил его в -1, и
условие (iCurrentDay <> -1) AND (час >= 3) было истинно на ПЕРВОМ же
скане → коррекция срабатывала на каждой загрузке, а не раз в сутки.
Лечение (в PRG_TimeCorrect):
  * холодный старт только запоминает день, коррекцию не делает;
  * после записи RTC читается обратно на следующем скане, отклонение
    >60 с копится в diRtcSetBias и вычитается из всех записей
    (перекос Set/Get ПЛК измеряет сам), тут же повторная запись;
  * 2 неудачи подряд → xTimeDriftCorrEnable:=FALSE + текст на экран;
  * шаг коррекции ограничен 600 с.
diRtcSetBias после первой коррекции должен показать -10800.
- PRG_AlarmLogSD: журнал 12 аварий на SD-карту
  /mnt/ufs/media/mmcblk0p1/ через CAA File (тип FILE.CAA.HANDLE),
  строки WSTRING/UTF-16LE + BOM. Требует библиотеку CAA File и
  карту FAT32/MBR. Не протестировано на объекте.

--- РОТАЦИЯ ЖУРНАЛОВ НА SD 04.08.2026 ---
Файлы стали ПОМЕСЯЧНЫМИ: alarms-MM-YYYY.log, pump_changes-MM-YYYY.log,
setpoints-MM-YYYY.log. Новый месяц → новый путь → файл создаётся сам
прежним автоматом (OPEN → NOT_EXIST → CREATE + BOM), отдельной логики
переключения месяца нет намеренно.
Новый FB_SdSpaceGuard раз в час (tSdCheckPeriod), при смене месяца и
после неудачной записи обходит каталог и чистит самый старый месяц по
двум независимым условиям, повторяя, пока условие держится.
Единственная настройка — номинал карты в выпадающем списке на экране
(iSdCardSize, 0=2 ГБ … 6=128 ГБ). Реальные ёмкости в таблице
audiSdCardMB: 1800/3600/7200/14500/29000/58000/116000 МиБ — взяты с
запасом вниз (производитель считает ГБ десятичными: 32 ГБ = 32·10⁹ Б =
30518 МиБ, плюс таблица разделов, две копии FAT и корневой каталог).
- Условие A — КВОТА (работает всегда): квота = ёмкость − 100 МБ
  резерва − чужие файлы. На 32 ГБ журналам достаётся ~28,9 ГБ. В квоту
  считаются только наши файлы; чужие вычитаются из ёмкости, но не
  удаляются. Содержимое вложенных папок не считается (DirList в
  глубину не ходит) — папку app.spk1xxm01 перекрывает резерв.
- Аварийный форс: 3 неудачные записи подряд = карта реально полна
  (в списке выбрали больше реального) → самый старый месяц удаляется
  безусловно. Одиночный сбой к удалению не приводит.
- «Самый старый» = минимальный ключ YYYY*12+MM-1 (сравнение строк дало
  бы 12-2025 «новее» 01-2026 — грабли).
- Файл текущего месяца удалить нельзя в принципе.
- Удаляются только имена, прошедшие полный разбор F_SdLogMonthKey;
  чужие файлы на карте не трогаются.
- Если удалять нечего, а квота превышена (вся история — один текущий
  месяц, раздутый дребезгом) — поднимается xSdLogQuotaStop и запись на
  SD прекращается. Снимается САМО на следующем месяце.
Алгоритмы прогнаны на исполняемой модели: см.
60-let-oktyabrya/docs/sd_guard_model_test.js (165 проверок, общая для
обоих проектов — код FB и функций идентичен).
