## ПОДКЛЮЧИТЬ В ПРОЕКТЕ — пункты 6–10

Скачивать не надо, идут с CODESYS. Но их нужно **добавить в Менеджер
библиотек проекта**, иначе компиляция ругается на неизвестные типы.

### 6. Standard
`TON` (100 экземпляров в проекте), `TOF` (2), `R_TRIG` (2),
`CONCAT`, `LEN`, `WCONCAT`, `WLEN`.
Обычно уже подключена.

### 7. SysTimeRtc
`SysTimeRtcGet`, `SysTimeRtcSet`, `SysTimeRtcConvertUtcToDate`,
тип `SYSTIMEDATE`.
Используется в `PRG_Fountain.st` и `PRG_TimeCorrect.st`.
⚠️ Системная — в обычном списке скрыта, см. Место 3 ниже.

### 8. CAA File
Пространство имён `FILE`: `Open`, `Read`, `Write`, `Close`, `Delete`,
`GetSize`, `Flush`, `DirOpen`, `DirList`, `DirClose`, режимы
`FILE.MODE.*`, коды `FILE.ERROR.*`, дескриптор `FILE.CAA.HANDLE`.
Вся запись журналов на SD: `PRG_AlarmLogSD.st`, `FB_SdSpaceGuard.st`,
`FB_SdCardSize.st`.
⚠️ Дескриптор объявлять как `FILE.CAA.HANDLE`, а не `CAA.HANDLE` —
иначе ошибка «ссылка на объект не указывает на экземпляр».

### 9. CAA Types Extern
Зависимость CAA File, тянется сама. Отдельно добавлять не нужно.

### 10. VisuElems
Библиотеки визуализации, добавляются автоматически при наличии
Менеджера визуализации. Вручную не трогать.

**Modbus COM / Master / Slave** — не библиотеки, а описания устройств.
Идут с CODESYS и таргет-пакетом, добавляются в дерево, а не через
Менеджер библиотек.

## ДИАЛОГ «СРЕДА ПРОЕКТА» ПРИ ПЕРВОМ ОТКРЫТИИ

При открытии проекта на чистой машине выскакивает окно
**«Среда проекта»**, закладка **«Незаданный плейсхолдер»**, с длинным
списком библиотек и колонками «Плейсхолдер / Рекомендуется / Действие».

### Что это

Проект ссылается на библиотеки через *плейсхолдеры* — имена без
привязки к конкретной версии. Версия подставляется из таргета при
открытии. На новой машине эта привязка ещё не сделана, и CODESYS
спрашивает разрешения её выполнить.

### Что нажимать

**`OK`.** Это не то же самое, что окно обновления версий. Здесь
плейсхолдеры **обязаны** быть разрешены, иначе проект не соберётся.
В колонке «Действие» уже стоит нужное — «Разрешить в 3.5.17.0».

Галочку «Проверять обновления при загрузке этого проекта» оставить
как есть.

### Про кнопку «Сделать все новейшими»

**Не нажимать** — но если нажали, паниковать не нужно.

«Новейшими» означает «новейшими **из установленных**». На свежей
машине установлен ровно один комплект версий — тот, что пришёл с SP17
и таргетом, поэтому «новейшая» и «рекомендуемая» там совпадают. Для
`CmpErrors` новейшая установленная — те же 3.3.1.40. Кнопка опасна на
машине, где накопилось несколько версий библиотек: тогда она подставит
не то, что рекомендовано.

**Если нажали случайно:**

1. Проект ещё открыт → `Файл → Закрыть проект` → на вопрос о
   сохранении ответить **«Не сохранять»**. Состояние вернулось.
2. Открыть заново, на диалоге нажать `OK`.
3. Проверка — **F11**. Ноль ошибок означает, что привязки корректны и
   откатывать нечего. Посмотреть привязки глазами:
   `Проект → Среда проекта…`

**Если успели сохранить** — файл проекта в git, откат байт в байт:

```
git status                                       # что вообще изменилось
git checkout -- 60-let-oktyabrya/60_years_v1.project
```

Скачивать проект заново не нужно никогда — git хранит точную копию.

## КУДА ЧТО ПОДКЛЮЧАЕТСЯ

Разные вещи ставятся в разных местах, и часть — на уровень среды, а не
проекта. «Установил, но не подключил в проекте» — самая частая ошибка.

Три из четырёх мест живут в одном меню — **«Инструменты»**:

![Меню «Инструменты» в CODESYS](img/07-menu-instrumenty.svg)

**Рис. 7.** Меню «Инструменты» — отсюда открываются три из четырёх мест

1. **CODESYS Installer…** — Место 1, пакеты `.package`: таргет ОВЕН
   и Mx110Drivers (пункты 2 и 3)
2. **Репозиторий библиотек…** — Место 2, **шаг 2а**: положить файл
   OwenVisuDialogs в среду (пункт 5). Шаг 2б делается потом, из дерева
   проекта
3. **Репозиторий устройств…** — Место 4: описания устройств
   (`.devdesc.xml`, EDS, GSD) — обычно не требуется

Шаг 2б — подключение библиотеки к проекту — делается **не отсюда**, а
из дерева проекта, через `Менеджер библиотек`.

### Место 1 — пакеты `.package` → уровень среды

```
Инструменты → CODESYS Installer… → Install File… → выбрать .package
```

В старых версиях среды пункт называется `Менеджер пакетов → Установить…`
Требует перезапуска CODESYS. Ставится один раз на машину.

Сюда идут пункты **2** и **3**.

Проверка: `Файл → Новый проект → Стандартный проект` — в списке
устройств должен быть СПК1хх [М01]. Пустой проект не сохранять.

### Место 2 — внешние библиотеки `.library` → ДВА шага подряд

**Пункт 5 (OwenVisuDialogs) проходит оба шага: сначала 2а, потом 2б.**
Это не выбор «или-или».

| Шаг | Что подаём | Как часто | Что получаем |
|---|---|---|---|
| **2а** | **файл** `.library` | один раз на машину | библиотека появилась в среде |
| **2б** | **имя** библиотеки | в каждом проекте | код её увидел |

После 2а библиотека установлена, но проекту всё ещё недоступна —
именно здесь чаще всего застревают.

**2а — положить файл в хранилище среды:**
```
Инструменты → Репозиторий библиотек… → Установить… → выбрать файл
```

⚠️ **Список в этом окне — это уже установленные библиотеки, а не файлы
на диске.** Окно ничего само не ищет. Пока не нажали «Установить…» и
не указали файл, вашей библиотеки там не будет — это нормально, а не
признак того, что что-то потерялось.

Если в диалоге выбора файла файл не виден — переключить фильтр типа
на `*.library`: по умолчанию может стоять `*.compiled-library`, а у
OwenVisuDialogs расширение именно `.library`.

Если после установки библиотеки всё равно нет в списке — проверить два
фильтра в верхней части окна репозитория:
- **«Расположение»** (Location) — должно быть **System**, а не User
- **«Компания»** (Company) — поставить **«(Все компании)»**, иначе
  показывается только один вендор

**2б — подключить к конкретному проекту:**
```
Менеджер библиотек (двойной клик в дереве) → Добавить библиотеку… → имя → OK
```

Здесь файл уже не нужен — библиотека выбирается по имени из того, что
установлено на шаге 2а.

### Место 3 — встроенные библиотеки → ТОЛЬКО шаг 2б

Скачивать и устанавливать нечего, нужно только добавить в проект:
```
Менеджер библиотек → Добавить библиотеку… → имя → OK
```

⚠️ **Системные библиотеки (`SysTimeRtc` и прочие `Sys*`) в обычном
списке не показываются.** Нажать **«Дополнительно…»** (Advanced) и
включить отображение всех библиотек — только тогда найдутся поиском.

Сюда идут пункты **6**–**9**.

### Место 4 — драйверы и утилиты → обычная установка Windows

Пункт **4** и всё из раздела «по необходимости». К CODESYS отношения
не имеют. Драйвер USB требует перезагрузки ПК.

## ПОРЯДОК УСТАНОВКИ С НУЛЯ

1. Пункт **1** — распаковать, `setup*.exe` **от администратора**.
2. Перезагрузить ПК (ставится служба CODESYS Gateway).
3. Пункт **2** — таргет, Место 1. Перезапустить среду.
4. Пункт **3** — Mx110Drivers, Место 1. Перезапустить среду.
5. Пункт **4** — драйвер USB. Перезагрузить ПК.
6. Пункт **5** — Место 2, шаг 2а.
7. Открыть проект. Выскочит окно «Среда проекта → Незаданный
   плейсхолдер» — нажать **OK** (не «Сделать все новейшими»).
   Если следом предложат обновить версии устройств и библиотек —
   **ничего не обновлять**. Подробнее — раздел про диалог выше.
8. Открыть `Менеджер библиотек`, сверить с пунктами **6**–**10**.
   Чего нет — добавить (Место 2 шаг 2б / Место 3).
9. **F11** → должно быть **0 ошибок**.

На машине скачаны `OwenStringUtils_v3.5.4.9.compiled-library` и
`OwenCommunication_v3.5.11.7.compiled-library`. **В коде `.st` они не

Ставить их не нужно. Единственная оговорка: они могли применяться в
визуализации, которую из исходников не видно. Практический критерий —
`F11`: если компиляция проходит без них, значит не нужны.

## ОТКУДА ВЗЯТ ЭТОТ СПИСОК
